## ⚠️ 空间页读不到数据的头号原因（务必先查这条）
空间页要显示某张表，**必须同时满足两条**：
1. 该表与页面建立了 page↔database 绑定（`tools/fix_page_binding.py` 可一键补绑/查看）；
2. 重导入页面时带上 `--databases` 声明这些表（`tools/publish_page.py` 已内置 13 张表）。

少任何一条，页面 `db.query` 那张表就永远返回空 —— 现象是**「飞书表里有数据，页面上却是空的」**。
2026-09-19 的「简历看不到」就是这个原因：新增的 简历优化/岗位JD/原始简历/素材库/面试题库/任务反馈 6 张表从没绑到页面上。2026-09-13 重构又新增「陪跑台·辅线知识库」为第 14 张表，已一并绑定 + 在 publish_page.py 声明。

## `tools/`（活脚本）
- `publish_page.py` — 把 `index.html` 发布到空间页（含 13 张表的 `--databases` 声明，**重发一律用它**）
- `fix_page_binding.py` — 查看/补齐 空间页↔数据表 绑定关系（页面空数据先跑这个）
- `_check_tables.py` — 打印各表真实记录数，判断"是数据没了还是页面没读到"
- `insert_*.py` — 往飞书表写入（素材库 / 知识卡 / 面试题 / 转岗复盘 / 简历优化）
- `create_resume_db.py` — 建简历优化表
- `dump_baodian.py` `extract_resume.py` — 导出宝典 / 提取简历 PDF
- `coach.py` — 飞书表通用读写辅助

## `archive/`（可删除）
放着早期增量补丁（`patch_v2~v8` 等，最终态已合进 `index.html`）、一次性初始化/修复脚本、临时文件、以及死副本 `架构师陪跑台.html`。**这些都不影响线上产品**。确认不需要后，直接删除整个 `archive/` 文件夹即可。

## 为什么 `index.html` / `data/` / `tools/` 留在根目录
发布脚本、入库脚本、每日 8:30 自动化都把这些路径**写死**在根目录下（如 `data/_db_ids.json`、`data/baodian_full.jsonl`）。若把它们移进子文件夹，会牵连脚本并可能导致**明天的自动出题失效**。因此生产文件保持原位，只把废弃物和无关项目清走/隔离，根目录即陪跑台项目本体。

## 每日自动化
- 名称：陪跑台 · 每日出题（8:30）
- 作用：每天生成 1 张知识卡 + 今日任务，强制检索 `data/baodian_full.jsonl` 并引用知识库
- 维护提示：改 `data/baodian_full.jsonl` 或 `data/_db_ids.json` 前先确认，否则自动化会断
